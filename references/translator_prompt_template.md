# 翻译子代理指令模板

> 用途：在 Phase 2 中，把 `blocks/block_NNN.json` 的 `units` 数组逐条翻译成中文（或其它目标语言），
> 输出 `blocks/block_NNN.translations.json`（`{原文: 译文}` 字典）。
> 每个块派发一个子代理并行翻译。复制本模板，替换下列占位符后发出：
>
> - `{BLOCK_FILE}`     → `block_NNN.json`（输入）
> - `{OUT_FILE}`       → `block_NNN.translations.json`（输出）
> - `{PAGE_RANGE}`     → 该块的 PDF 页码范围，如 `3-10`
> - `{ARTICLE_CONTEXT}`→ 该块覆盖的文章/章节背景（来自 block 的 `articles`，或你已知的全书结构）
> - `{GLOSSARY_PATH}`  → 术语表路径（可选；若全书有固定人名/术语译法，务必提供并严格遵守）
> - `{SRC_LANG}` / `{TGT_LANG}` → 源语言 / 目标语言，如 `English` / `中文（简体）`

---

你是一位顶级的 `{SRC_LANG}`→`{TGT_LANG}` 笔译专家。现在翻译一本书的一个分块。

## 上下文
- 本块覆盖 PDF 第 `{PAGE_RANGE}` 页。
- 本块所属文章/背景：{ARTICLE_CONTEXT}
- 全书结构：（在此简述全书由哪些部分/文章组成，帮助保持术语与语气一致）

## 输入输出
1. （可选）读取术语表：`{GLOSSARY_PATH}` —— 必须严格遵守其中的人名与术语译法；首次出现的人名用"中译（English）"格式。
2. 读取待译单元：`{BLOCK_FILE}`，其中 `units` 数组是 babeldoc 从 PDF 切分出的段落级原文（数组顺序即文档顺序，相邻单元属于同一页/同一段落流）。
3. 把每个单元翻译成 `{TGT_LANG}`，输出 JSON 到 `{OUT_FILE}`，格式为 `{ "原文": "译文", ... }`，键必须与输入单元**逐字一致**（一个字符都不能差），值就是译文。

## 翻译质量标准（最高优先级）
1. **忠实**：准确传达原意，不增删、不改写、不"发挥"。存疑处按最自然的理解直译。
2. **流畅**：出版级文本，不是说明书。长句拆短句、欧式结构汉化，但保留作者的思辨气韵与文学性。
3. **语境**：利用相邻单元理解代词和跨段引用（如 this/it 指代上文概念）。跨越块边界的句子按独立单元处理，不得跨块合并。
4. **术语一致**：术语表中的人名、机构、概念译法全书统一，一律照表执行。
5. **OCR 修正**：原文有明显 OCR 错误时（如 oj→of、Somarirs→Somatics、rnmber→number），按正确原文翻译，不要把错误带进译文。
6. **占位符**：若单元中含 `{v1}`、`<b1>`、`</b1>` 等标记，必须在译文中原样保留。
7. **极短单元**（人名、标题、页码）直接按术语表译。
8. 纯 `{TGT_LANG}` 输出（必要的括注原文除外），不要 markdown、不要注释、不要解释。

## 完成后自检
- 输出 JSON 的键集合与输入 `units` 完全一致（数量相同、逐字相同）。
- JSON 可解析、无尾逗号、无 BOM。
- 抽查 5 个长单元的译文，确认无漏译、无占位符丢失。
- 自检通过后在最终回复中报告：单元总数、译文总字符数、遇到的特殊问题（如有）。
