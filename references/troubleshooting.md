# Troubleshooting (collect → build → replay)

| Symptom | Cause | Fix |
|---|---|---|
| `ScannedPDFError` / "Scanned PDF detected" at collect | PDF is a scan: page images contain the English, text layer is invisible OCR | set `ME_OCR_WORKAROUND=1` for collect AND replay. White-fill boxes cover the image's English, black text on top. No OCR engine needed. Pages with a completely empty text layer (covers) cannot be translated — expected (preflight lists them upfront). |
| `FzErrorSystem: code=2: cannot open file ...` at save time | Windows MAX_PATH: input stem (often a long book title) is mirrored into working/output paths > 260 chars | collect/replay now detect long input paths and run via a short copy in `%TEMP%\me_short\<sha8>\`, copying the PDFs back to `out_<mode>/`; retry once after upgrading. If it persists (extreme work-dir path), use a short work dir or copy the PDF to `C:\tmp\book.pdf`. preflight still warns early. |
| `UnicodeEncodeError` printing sources/warnings on Windows | cp936 console vs CJK output | `PYTHONUTF8=1` (PowerShell: `$env:PYTHONUTF8='1'`) before running any script; scripts also reconfigure stdout defensively |
| `bitstring` / `BitStream` ImportError from babeldoc | bitstring 5.x broke babeldoc's import | `pip install "bitstring<5"` |
| build exits 3: `tiktoken unavailable` | encoding files not downloadable (offline first run) | `pip install tiktoken`; first use downloads o200k_base (needs network once), then works offline. Never bypass — ratio validation would be silently skipped. |
| `prompts=0` after collect | wrong page range, image-only pages, or PDF path typo | verify page range; run `preflight.py` to see per-page text-layer stats |
| `pdf_pages=?` / `estimate: unavailable` in `pipe_status.py` | PyMuPDF (`fitz`) is missing or the stamp's input PDF path no longer exists | install PyMuPDF (`pip install pymupdf`) so page count and estimates work, or pass an explicit page range; a missing PDF path cannot be estimated |
| `unparsed > 0` | prompt matched neither batch nor single marker (babeldoc template changed) | read `me_work/unparsed.jsonl`; extend `INPUT_MARKER`/`SINGLE_MARKER` in me_translator.py, delete the file, re-collect |
| replay ERROR `collect/replay mismatch` (exit 2) | page range / PDF content sha / source language / target language differ from `run_stamp.json` | rerun replay with the collected values, or re-collect for the new input/languages (a different PDF, a different `ME_LANG_IN`/`ME_LANG_OUT`, or a non-extending page range auto-archives the old run) |
| collect on a new PDF or language kept old stats/prompts | (fixed) — driver archives all previous artifacts (prompts, outputs, indexes, chunks, chunk retry/fix metadata, reports, `out_collect`/`out_replay`) when the input fingerprint changes | verify `me_work/archive/` received them; rerun export after the new collect |
| want to extend a page range (1-5 → 1-15) | stamp records the collect range | just re-collect with the new range **on the same PDF and languages** (append mode keeps old prompts and skips keys already logged); export syncs `zh_texts.json` keeping existing translations; translate only the `remaining` count, build, replay with the new range. Shrinking the range (or `ALL` → a subset) archives instead — re-collect from scratch and retranslate. |
| build `RESULT: NEEDS_FIX` (coverage) | some values empty in zh_texts.json / slices | fill the listed sources (export prints `remaining` too) |
| build `RESULT: NEEDS_FIX` (validation) | same-as-input >10tok / ratio out of (0.3,3) / `<bN>` tag mismatch / paragraph count differs | each error names the source; fix that value, rerun build |
| build `unknown key(s) not present in src_texts` | zh object has keys from another run / hand-edited junk | remove the listed keys (or re-run export, which prunes them with a notice) |
| build `conflicting translations ... in zh_slice` | two slices translated the same source differently | pick one value; delete the other entry from its slice |
| glossary warnings (non-fatal) | a segment contains a glossary source term but not its target term | review each: fix genuine misses in the translation; delete the glossary entry if the term is intentionally rendered differently |
| replay `missing_llm>0` / WARNING / exit 1 | prompt key absent from llm_outputs.json (stale prompts, edited prompts) | inspect `missing.jsonl`; translate those sources, rebuild, replay (stale miss logs are cleared at replay start) |
| translated text invisible / double English | scanned image shows through where translation layer is thin | ensure `ME_OCR_WORKAROUND=1`; if page has 0 text chars it's image-only — cannot be fixed by this pipeline |
| collect looked fine but replay output identical to input | capability probe failed (exception in `do_llm_translate(None)`) or wrong mode env | rerun replay; logs must show `Successful: N, Fallback: 0` |
| cover/title page still English | no text layer on that page (0 extractable chars) | expected; tell the user those pages need manual typesetting or real OCR re-creation |
| collect is slow (~1 min even for 5 pages) | babeldoc unconditionally typesets + renders output PDFs after translating (`high_level.py`); no supported switch to skip rendering while keeping the translation stage | accept the cost; collect runs once per input/range. Skipping would require a version-coupled monkeypatch of `PDFCreater.write` — deliberately not supported. |
| slices exist but build still reports missing | slices were generated before new sources were collected | rerun `split_work.py --force` (seeds existing translations), refill the new `""` entries |
| pure-pipe: `llm_chunk_N.json` missing / merged keys < expected | a subagent didn't return its file, or wrote wrong keys | check `me_work/` for each `llm_chunk_N.json`; re-run only the missing chunk's subagent (its `chunk_N.json` still holds the assignment) |
| pure-pipe: `TAG-SEQUENCE PROBLEMS > 0` | the agent dropped/added/renumbered a `<bN>` tag | merge writes `retry.jsonl`; run `pipe_prep.py --from-retry retry.jsonl`, translate `chunk_retry_*.json` → `llm_chunk_retry_*.json`, merge again. Retry values override older values; a newer normal chunk wins and merge reports `retry_ignored`. Do NOT hand-edit tags — re-translate. |
| pure-pipe: batch value not valid JSON array | subagent returned a string/object instead of `[{"id","output"}]` | re-run that chunk's subagent; the instruction mandates the array form |
| replay exits 3: preflight failed | prompts.jsonl has prompts with no usable key or exact-text translation; replay refuses before rendering | run pipe_merge.py, translate coverage_missing.jsonl via pipe_prep.py --from-missing, merge again. --allow-misses only for deliberate inspection. |
| merge exits 3: conflicting duplicate keys | several chunk files translate the same key differently (retry rounds, overlapping chunks) | inspect the listed files (the report names the file actually kept and every file whose value was overwritten, including a third file winning); re-run the chunk that should win, or pass --conflict last to keep the newest file. Never hand-edit llm_outputs.json. |
| merge exits 3: `RETRY VALUES WITH BAD TAGS` | a retry/fix value has a `<bN>` sequence that does not match its source (bad hand edit or a confused subagent) | the value is not applied and stays in retry.jsonl (reported as `retry_bad_tags`), even if the normal value is fine. Re-translate that text via `pipe_prep.py --from-retry retry.jsonl`; never hand-edit tags. |
| `preflight.py` / `render_check.py` exit 2: `PyMuPDF is required` | the `fitz` import is missing in this Python environment | `pip install pymupdf` (babeldoc usually installs it). Collect/replay do not need it. |
| --chunks 8 writes ~70 chunks | --max-chars 32000 caps chunk size; equal-count chunks of a book would time out | expected: --chunks is a target, the cap wins. Raise --max-chars only if your subagents handle it; the script prints a note. |
| glossary terms ignored by the agent | the chunk instruction lists them, but a subagent paraphrased anyway | rerun that chunk emphasising rule 7; check `GLOSSARY WARNINGS` / `glossary_warnings.jsonl` from merge (advisory). Verify the pair is correct (motor vs motorcycle boundaries). |
| `pipe_prep` says `nothing to translate` | every source in `prompts.jsonl` already has a non-empty translation in `text_index.json` (incremental default) | expected after a complete run. Use `--all` to re-chunk everything (quality pass), or collect an extended range first to add new prompts. |
| Windows console mangles long run logs | cp936 console vs BabelDOC CJK log lines | add --log-file replay.log; the UTF-8 file is complete even if the console is not. |
| merge prints `RETRY ITEMS` / retry.jsonl is non-empty | tag/id/empty defects, coverage gaps, or (with --import-missing) replay misses remain | `pipe_prep.py --from-retry retry.jsonl` → translate `chunk_retry_*.json` → `llm_chunk_retry_*.json` → merge again. The file disappears when clean. `--retry-content` only if you want content warnings re-translated. |
| merge prints `ignored N stale text-fix value(s)` | a normal `llm_chunk_*.json` covering the same source is newer than `llm_chunk_retry_*.json` / `llm_chunk_fix_*.json` | expected after a deliberate re-translation: the newer normal value wins and `retry_ignored` records it. Regenerate the retry file after the normal chunk if the retry value should win. |
| replay logs `missing_llm>0` / `missing_fb>0` | the engine requested a key or plain-path text that outputs did not contain | `pipe_merge.py --import-missing` folds those sources into `retry.jsonl` (already-covered sources are skipped), then the normal retry loop; replay again. |
| merge prints `CONTENT WARNINGS` | output equals the source (>10 words), a long segment has no Chinese, or the length ratio is extreme | inspect content_warnings.jsonl. Names/bibliography are exempt by pattern; a real paragraph hit means it would ship in English — add `--retry-content` to fold it into retry.jsonl, or re-translate manually. Warnings are advisory; `--strict` makes them exit 3. |
| merge prints `GLOSSARY WARNINGS` | a source segment contains a glossary term but the output lacks the expected target term | inspect glossary_warnings.jsonl; if the rendering is genuinely wrong, fix the glossary entry or retranslate that segment manually. Advisory only (never blocks replay); `--no-glossary` skips the check. |
| preflight `plain-path sources=N uncovered>0` | a paragraph took BabelDOC's plain `do_translate` path during collect and has no translation under sha(text) | translate that source, rerun `pipe_merge.py` (it backfills fallback_outputs.json from the whole text index), then replay. `--allow-misses` is not a fix. |
| replay still contains English although merge said COMPLETE | the engine used the plain path, not a `b:`/`s:` key; older work dirs had an empty fallback_outputs.json when collect never used that path | rerun `pipe_merge.py` after the upgrade (writes every indexed text into fallback_outputs.json); runtime also consults text_index.json. Verify with `pipe_status.py`: fallback uncovered=0. |

## Sanity checklist before delivering

1. `preflight.py` report reviewed (paths, empty pages, OCR workaround?)
2. collect: `prompts=N  unparsed=0`; same PDF + languages + range as replay
3. build: `RESULT: OK` (glossary warnings acceptable after review)
3b. merge: `RESULT: COMPLETE`, `retry.jsonl` absent, byte-identical tags,
   content + glossary warnings reviewed; replayed languages match the stamp
4. replay: preflight missing=0; Successful: N  Fallback: 0; missing_llm=0 missing_fb=0; exit 0
5. `selftest.py --work <work>` passes (synthetic loop + real work dir audit)
6. `render_check.py` PNGs: Chinese present, no bleed-through English,
   page numbers/margins intact, cross-page paragraphs coherent.
